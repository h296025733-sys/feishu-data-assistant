# 飞书经营数据助手

这是我做的飞书经营数据助手。使用者在群里提问或发出更新指令，机器人读取多维表格，返回可复核的统计结果，并在配置允许的范围内同步数据。

模型负责理解问题与组织表达，筛选、去重、计数、求和和排名由 TypeScript 执行。多店铺配置、群聊路由和各店铺凭证分开管理，避免把不同业务的数据混在一起。

## 主要实现

- XLSX / CSV 导入检查、字段识别和导入预演。
- 飞书多维表格读取、确定性查询和结构化回答。
- 群聊与租户路由、用户权限、澄清与会话范围。
- 对接独立 TikTok 数据管线，按目标日期和字段规则更新已有记录。
- 写前计划与备份、幂等更新、写后核对和显式回滚。
- 定时报告、数据质量与店铺异常提醒。
- 附带经营工作台插件源码，提供表格矩阵和关联查看界面。

```text
消息 → 权限 / 店铺路由 → 意图识别 → 确定性查询或更新计划
     → 飞书 / TikTok 适配层 → 核对结果 → 回复与任务记录
```

## 本地准备

建议 Node.js 24+，依赖使用 pnpm。

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
pnpm typecheck
pnpm test
```

示例配置的复制方式见 [本地配置](docs/local-configuration.md)。

`MODEL_PROVIDER=mock` 可用于本地开发模型适配层；它不代表真实模型或飞书链路已验证。接真实应用时，需要填写自己的飞书授权、表格字段映射、允许用户和租户配置，再检查导入预演。

`src/query/` 是查询，`src/feishu/` 是接口适配，`src/realtime/` 是更新与回滚，`apps/` 是工作台插件。只读 TikTok 管线见 [tiktok-shop-data-pipeline](https://github.com/h296025733-sys/tiktok-shop-data-pipeline)。

公开版保留实现和测试，企业表格地址、联系人、店铺标识和正式配置改为示例。历史迁移工具中的 `demo_` 标识需要按自己的表结构配置；不要将它们当作已接入的真实企业应用。
